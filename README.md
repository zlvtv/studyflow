# StudyFlow

Курсовой проект Златы Жилинко, группа 5140904/60202.

Планировщик учебных заданий: лабораторные, практические и подготовку к занятиям
можно собрать в одном списке, разделить по предметам и отсортировать по сроку.
У задания есть приоритет, статус и заметка — например, номер варианта или ссылка
на методичку. В боковой панели показывается ближайшая незавершённая работа.

В первой версии один пользователь. Регистрации, уведомлений и синхронизации
с учебными системами нет. Приложение рассчитано на запуск на своём компьютере.

## Запуск

Понадобятся Docker с Compose v2, Bash и curl. Команды выполняются из папки проекта.

```bash
cp .env.example .env
```

Открой `.env` и заполни `POSTGRES_PASSWORD` своим паролем. Остальные значения
для первого запуска можно оставить как есть.

```bash
docker compose build
docker compose up -d --wait db
docker compose run --rm --no-deps backend alembic upgrade head
docker compose up -d --no-build --wait
```

Открой [localhost:8088](http://127.0.0.1:8088).
Пустой список можно заполнить вручную или добавить шесть учебных примеров:

```bash
python3 infra/seed_demo.py
```

Примеры включают просроченную работу, задание на сегодня и несколько будущих
сроков. Повторный запуск пропускает уже добавленные примеры.

Для остановки используй `docker compose down`. Задания остаются в томе PostgreSQL.
Ключ `-v` удаляет этот том вместе с данными.

## Как устроен проект

Интерфейс написан на React и TypeScript, собирается Vite. Nginx отдаёт страницу
и пересылает `/api/` в FastAPI. Сервер работает с PostgreSQL через SQLAlchemy;
структура таблицы меняется миграциями Alembic.

- `frontend/src/App.tsx` — список, фильтры и состояние страницы;
- `frontend/src/components/` — форма, строка задания и диалоги;
- `frontend/src/tasks.ts` — отбор по срокам, сортировка и проверка формы;
- `backend/app/` — модель задания, схемы данных и HTTP-маршруты;
- `backend/alembic/` — история изменений базы;
- `infra/` — Nginx, обновление, резервные копии и откат версии.

Просроченным считается незавершённое задание с датой раньше сегодняшней.
Срок «сегодня» ещё не просрочен. Представление «Ближайшие 7 дней» включает
сегодняшний день и следующие шесть, а не календарную неделю.

## Тесты и CI

Pytest проверяет API, Vitest — сроки и фильтры, HTTP-клиент и действия в форме.
Для скриптов обновления есть проверки отказа миграции, неудачного запуска,
возврата версии и блокировки одновременных обновлений.

[Разработка и команды проверок](docs/development.md) ·
[API и решения по архитектуре](docs/architecture.md)

Исходники размещаются в [zlvtv/studyflow](https://github.com/zlvtv/studyflow).
GitHub Actions запускает проверки и тест контейнерного обновления. В теме курсовой
указан GitLab CI/CD, поэтому в репозитории также есть `.gitlab-ci.yml` для запуска
на собственном Runner. Его настройка описана [отдельно](docs/gitlab-setup.md).

[Обновление, резервные копии и откат](docs/deployment.md) ·
[Результаты последней проверки](docs/validation.md)

Если приложение не запустилось, начни с `docker compose ps` и
`docker compose logs --tail 100 backend frontend db`.
Проверка API и соединения с базой доступна на `/health`, документация запросов — на `/docs`.
