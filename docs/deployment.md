# Обновление и обслуживание

Для обновлений используется постоянная папка вне временного checkout CI.
В ней лежат `.env`, резервные копии, `current-tag`, `previous-tag` и временная
блокировка обслуживания.

```bash
export STUDYFLOW_DEPLOY_DIR="$(pwd)/.studyflow-runtime/local"
mkdir -p "$STUDYFLOW_DEPLOY_DIR"
cp .env.example "$STUDYFLOW_DEPLOY_DIR/.env"
chmod 600 "$STUDYFLOW_DEPLOY_DIR/.env"
```

Заполни пароль в созданном `.env`. После инициализации PostgreSQL изменение этого
значения само по себе не меняет пароль роли в базе — для этого нужна отдельная
команда PostgreSQL.

## Первая и вторая версии

Из корня проекта, с работающим Docker:

```bash
APP_TAG=v1 docker compose --env-file "$STUDYFLOW_DEPLOY_DIR/.env" build
bash infra/deploy.sh v1
```

После изменения исходников собери другую метку:

```bash
APP_TAG=v2 docker compose --env-file "$STUDYFLOW_DEPLOY_DIR/.env" build
bash infra/deploy.sh v2
```

В CI вместо `v1` или `v2` используется полный SHA коммита. Образы остаются на
локальном Docker-хосте. Скрипт не подменяет отсутствующий образ загрузкой из registry.

`deploy.sh` запускает базу, делает `pg_dump`, применяет миграцию одноразовым
контейнером и запускает сервисы. Затем проверяет страницу, `/health` с ожидаемой
версией и список задач. Только успешная версия записывается в `current-tag`.

Если новая версия не прошла проверку, скрипт пытается вернуть прежние образы и
завершает задание CI с ошибкой. Если не заработала и прежняя версия, это отдельно
указывается в логе. Для первой неудачной установки возвращать ещё нечего.

## Откат

```bash
bash infra/rollback.sh
# Или указать сохранённую метку:
bash infra/rollback.sh v1
```

Nginx-конфигурация входит в frontend-образ и возвращается вместе с ним.
Миграции выполняются отдельно от запуска API: старый образ не должен пытаться
применить ревизию, которой нет в его исходниках.

Откат меняет код, но не содержимое базы. Новая миграция должна оставаться совместимой
с предыдущим образом. Автоматический downgrade и замена рабочей базы дампом не
выполняются, поскольку они могут удалить записи, появившиеся после копирования.

## Копия и проверка восстановления

```bash
bash infra/backup.sh
bash infra/restore-test.sh /полный/путь/к/копии.dump
```

Копии записываются в `backups` с доступом только владельцу. Проверка восстановления
создаёт отдельный контейнер без сети и временный том, выполняет `pg_restore` и
запрос количества заданий. Затем удаляет только эти временные ресурсы.
Срок хранения копий пока задаётся вручную.

`deploy.lock` не даёт двум командам обслуживания выполняться одновременно.
Если компьютер выключился посреди обновления, сначала проверь состояние сервисов
и процессов, затем удали оставшуюся пустую папку блокировки.

```bash
docker compose --env-file "$STUDYFLOW_DEPLOY_DIR/.env" ps
docker compose --env-file "$STUDYFLOW_DEPLOY_DIR/.env" logs --tail 100
```
